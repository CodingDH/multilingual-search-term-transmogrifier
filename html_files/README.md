# HTML Review Tools

This folder contains local, single-file HTML tools for reviewing pipeline outputs. Open them in a browser and use the page's file picker to load the relevant CSV. No local server is required.

The HTML files do not write directly back into the repository. Each reviewer downloads an edited CSV. Save that downloaded file to the path listed below before running the next script or notebook.

## Recommended Order

1. **Family label policy**
   - Run `python scripts/review/build_family_analysis_mapping.py`
   - Open `family_analysis_mapping_reviewer.html`
   - Load `datasets/metadata_files/family_analysis_mapping.csv`
   - Download and save as `datasets/metadata_files/family_analysis_mapping_reviewed.csv`

2. **Language-to-family reconciliation**
   - Run `python scripts/review/build_family_reconciliation_review.py`
   - Open `family_reconciliation_reviewer.html`
   - Load `datasets/metadata_files/family_reconciliation_review.csv`
   - Download and save as `datasets/metadata_files/family_reconciliation_reviewed.csv`
   - Run `python scripts/review/apply_family_review_metadata.py`

3. **Translation output review**
   - Run notebook 02 far enough to generate `automated_review_signals.csv`
   - Run `python scripts/review/build_review_explorer_data.py --term "Digital Humanities"`
   - Open `review_explorer.html`
   - Load `datasets/translated_terms/digital_humanities/evaluation/review_explorer_data.csv`
   - Download and save as `datasets/translated_terms/digital_humanities/evaluation/manual_exclusions.csv`

4. **Search-term review**
   - Run `python scripts/generate_search_terms.py`
   - Open `search_term_reviewer.html`
   - Load `datasets/translated_terms/digital_humanities/search_terms/grouped_translated_terms.csv`
   - Download and save as `datasets/translated_terms/digital_humanities/search_terms/reviewed_grouped_translated_terms.csv`

5. **Search-result relevance review**
   - Finish running `searching_for_DH/data_generation_scripts/generate_search_data.py`
   - Run `python scripts/review/build_search_relevance_review.py`
   - Open `search_relevance_reviewer.html`
   - Load `datasets/translated_terms/digital_humanities/search_terms/search_result_relevance_review.csv`
   - Download and save as `datasets/translated_terms/digital_humanities/search_terms/search_result_relevance_reviewed.csv`

## Tool Details

### `family_analysis_mapping_reviewer.html`

Use this first in the family-review workflow. It reviews one row per current `family_name_reconciled` value and decides the aggregate label used for `family_name_analysis`.

Typical decisions:

- preserve a Glottolog/reviewed family label as-is
- normalize spelling or naming variants
- mark special non-family categories for analysis
- send broad or problematic labels to row-level reconciliation

Generated by:

```bash
python scripts/review/build_family_analysis_mapping.py
```

Consumed later by:

```bash
python scripts/review/build_family_reconciliation_review.py
python scripts/review/apply_family_review_metadata.py
```

### `family_reconciliation_reviewer.html`

Use this after the family analysis mapping is reviewed. It is the row-level family reviewer. It combines:

- ISO/Glottolog disagreement pairs from `family_reconciliation.csv`
- JSON fallback rows where `language_family_assignments.json` supplied the raw family assignment
- policy context from `family_analysis_mapping_reviewed.csv`, when available

The normal input is `family_reconciliation_review.csv`, built by:

```bash
python scripts/review/build_family_reconciliation_review.py
```

The page can also load an older pair-only `family_reconciliation.csv`, but the unified `family_reconciliation_review.csv` workflow is the current one.

After saving `family_reconciliation_reviewed.csv`, run:

```bash
python scripts/review/apply_family_review_metadata.py
```

That script writes `datasets/metadata_files/language_codes_comprehensive_family_reviewed.csv`, which downstream notebooks and `get_language_family()` prefer when present.

### `review_explorer.html`

Use this after notebook 02 has generated automated review signals and after `build_review_explorer_data.py` has merged them with the translation outputs.

Generated by:

```bash
python scripts/review/build_review_explorer_data.py --term "Digital Humanities"
```

Input:

```text
datasets/translated_terms/digital_humanities/evaluation/review_explorer_data.csv
```

The reviewer shows one row per language, with:

- automated review flags
- translation clusters
- service/prompt outputs
- rationales
- Wikipedia and direct MT reference terms
- controls for excluding translations or terms
- notes and term corrections

Primary output:

```text
datasets/translated_terms/digital_humanities/evaluation/manual_exclusions.csv
```

`manual_exclusions.csv` is consumed by downstream analysis scripts, including `explore_disagreements.py`, later notebooks, and search-term generation.

### `search_term_reviewer.html`

Use this after `scripts/generate_search_terms.py` has created grouped search terms.

Input:

```text
datasets/translated_terms/digital_humanities/search_terms/grouped_translated_terms.csv
```

The reviewer is for final search-term decisions:

- resolving directionality conflicts
- checking grouped language-code provenance
- deciding whether a term should be kept
- producing the search-ready CSV used by the GitHub search workflow

Output:

```text
datasets/translated_terms/digital_humanities/search_terms/reviewed_grouped_translated_terms.csv
```

Notebook 09 reads this reviewed search-term file when analyzing GitHub search results.

### `search_relevance_reviewer.html`

Use this after the GitHub search run finishes. The builder deduplicates GitHub items within each term and separates phrase-search repositories, topic-derived repositories, issues, pull requests, individual users, and organizations. Representative samples from all six groups show how each term produced its results.

Each term also reports how many results are exclusive to that term, shared with another term, already covered by the English `digital humanities` query, or new beyond English. The overlap panel draws a compact term-neighborhood graph and lists the ten alternative terms with the greatest material overlap. The builder also writes the complete edge list to `search_result_term_overlap_edges.csv` and global multiplicity counts to `search_result_overlap_summary.csv`; Notebook 09 uses both for its cluster analysis.

The generated Digital Humanities queue contains reviewed assessments and Notebook 09 applies exclusions from this reviewed artifact.

```bash
python scripts/review/build_search_relevance_review.py
```

The reviewer keeps three decisions separate:

- whether the term itself is credible, ambiguous, or suspect;
- whether its retrieved results are mostly relevant, mixed, or mostly irrelevant;
- a derived downstream status: retain, retain while tracking relevance, or exclude.

Save the download as:

```text
datasets/translated_terms/digital_humanities/search_terms/search_result_relevance_reviewed.csv
```

Rebuilding the queue preserves decisions from that reviewed file by normalized search term.

## Notes

- These tools rely on browser-side JavaScript and `localStorage`. If a page seems to remember stale decisions, clear the page's local storage or reload the saved CSV explicitly.
- Use the current generated CSVs rather than files in `older_datasets` unless you are intentionally auditing historical behavior.
- Keep downloaded filenames exact where possible. Several scripts look for the reviewed filenames listed above.
